# ko-quality 스모크 셋

스킬 유/무 베이스라인 비교용. 각 케이스를 스킬 없는 세션과 있는 세션에서
1회씩 실행하고 출력을 나란히 비교한다. 통과 기준은 케이스별 "확인 항목".

## 케이스 1 — 경량 / Slack 공지

지시: "팀 채널에 올릴 배포 지연 공지를 3~4문장으로 써줘. 원인은 마이그레이션
스크립트 오류, 새 배포 예정은 내일 오전."

확인 항목: 번역투·AI 상투어 없음, 쉼표 과다 없음, 채널 톤(해요체 폴백) 유지,
문장 길이 변화가 자연스러움.

## 케이스 2 — 경량 / 한국어 커밋 메시지

지시: "이 diff 커밋 메시지를 한국어로 써줘" (statusline 색상 로직 수정 같은
작은 diff 제공).

확인 항목: 저장소 기존 커밋 이력의 종결형 관례를 따름(에이전트 저작 커밋
제외), 번역투 없음, 제목이 간결함.

## 케이스 3 — 중량 / README 섹션

지시: "이 저장소 README에 들어갈 '설치' 섹션을 한국어로 작성해줘."

확인 항목: 검수 서브에이전트가 실행됨, 이웃 문서 컨벤션 참조함, 검수 요약
2~3줄이 남음, S1 잔존 없음.

## 케이스 4 — 검수 파이프라인 (오염 문단 교정)

지시: 아래 문단을 주고 "이걸 공유용 문서에 넣을 건데 다듬어줘".

> 이 기능은 사용자들에게 다양한 편의성을 제공함으로써, 전반적인 경험을
> 향상시키는 것을 목표로 하고 있습니다. 또한, 데이터에 대한 분석을 통해,
> 인사이트가 도출되어지는 구조로 되어 있으며, 이를 통해 개선이 이루어질 수
> 있습니다.

확인 항목: 번역투(에 대한/을 통해/되어지는), 명사화 남용, 쉼표 과다, AI
상투어(다양한/전반적인/향상)가 발견 사항으로 잡히고 교정됨. 의미는 보존됨.

## 케이스 5 — 경계 / 오발동 방지

지시: 영어 커밋 메시지를 쓰는 평범한 작업, 그리고 한국어 일상 질문("이 함수
뭐 하는 거야?")에 대한 답변.

확인 항목: 두 경우 모두 ko-quality가 발동하지 않음. 특히 영어 커밋을
한국어로 바꾸지 않음.

## 케이스 6 — 실전 / 세션 어휘 유출 위험이 높은 문서

지시: 긴 설계 세션 끝에 "지금까지 만든 것을 팀에 소개하는 문서를 써줘".

확인 항목: 세션 내부 용어(모드 이름, 원칙 ID, 내부 라벨)가 정의 없이 새어
나가지 않음(KO-23), 연어 직역("수동으로 부른다") 없음(KO-09), 독자 기준 용어
선택(KO-26). 세션 컨텍스트가 클수록 유출 압력이 커지므로 짧은 케이스보다
변별력이 높다.
