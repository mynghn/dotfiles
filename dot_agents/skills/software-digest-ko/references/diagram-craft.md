## 팔레트는 대상의 상태에서 뽑는다

스타일을 잡기 전에 **이 설명이 실제로 딛고 선 구분 두세 개**를 적어라. 문서의
절이 아니라 대상의 상태다. 전달된 작업물이면 대개 다음 중 하나다.

- `그대로 / 추가됨 / 제거됨` — 변경
- `뜨거운 경로 / 찬 경로` — 일이 실제로 일어나는 곳
- `이전 / 이후` — 마이그레이션이나 수정
- `호출자 / 경계 / 피호출자` — 경계를 넘는 이야기
- `안전 / 보호됨 / 무방비` — 동시성이나 검증 이야기

각 상태에 현실의 논리가 있는 색조를 준다. 정돈되고 검증된 것은 깊은 청록,
경합이나 주의는 황토, 멈춤이나 실패는 벽돌빛. 중립색은 주 강조색 쪽으로 아주
살짝 기울여 바탕이 기본값이 아니라 고른 색으로 읽히게 한다. 범례는 첫 그림
근처에 한 번만 두고, 다시 설명하지 않는다.

인코딩을 정직하게 지키는 규칙 둘.

- **색조만으로 의미를 지우지 마라.** 색조마다 모양·점선 패턴·위치·라벨 중
  하나를 짝지어라. 흑백으로 인쇄해도, 색각이 다른 눈으로 봐도 살아남아야 한다.
  `stroke-dasharray="5 4"` + 옅은 채움 + 상태 색조는 "불확실하거나 동시적"을
  세 채널로 겹쳐 말하는 것이다.
- **팔레트를 반증해 보라.** 완성된 팔레트가 다른 대상에도 똑같이 들어맞는다면
  도출을 건너뛴 것이다. 상태 목록으로 돌아가라.

## 질문마다 맞는 그림

| 독자의 질문 | 그림 |
|---|---|
| 부품이 무엇이고 무엇이 무엇과 말하나? | 노드-엣지 다이어그램, 인라인 SVG |
| 무슨 일이 어떤 순서로, 어느 컴포넌트를 거쳐 일어나나? | 시퀀스 또는 스윔레인 |
| 요청 하나, 레코드 하나가 어떤 모양을 지나가나? | 파이프라인·플로우, 왼쪽에서 오른쪽으로 |
| 무엇이 바뀌었나? | 이전/이후 한 쌍. 눈이 비교하도록 구조를 똑같이 |
| 어떤 상태들에 있을 수 있고 무엇이 상태를 옮기나? | 상태 기계 |
| 이게 더 큰 시스템 어디에 앉아 있나? | 컨텍스트 다이어그램. 대상은 채우고 이웃은 윤곽선만 |
| 얼마나, 몇 개, 어떻게 퍼져 있나? | 차트 — 그 수치가 논지를 질 때만 |

차트는 평범한 정직함의 규칙을 따른다. 막대는 0에서 시작하고, 3D는 절대 쓰지
않고, 파이는 여섯 조각 미만의 대략적인 분할에만 쓰고, 두 축에 라벨을 달고,
계열은 범례를 찾아가게 하지 말고 그 자리에 직접 이름을 붙인다. 오해를 부르는
차트는 변장한 누락이다.

## SVG 프리미티브

SVG는 손으로 쓴다. 아래 전부가 테마 변수를 읽으므로 다크 모드에서도 살아남는다.

**화살표 달린 방향 엣지**

```html
<defs>
  <marker id="ah" markerWidth="10" markerHeight="10" refX="8" refY="5" orient="auto">
    <path d="M0,0 L10,5 L0,10 z" fill="var(--state-a)"/>
  </marker>
</defs>
<line x1="166" y1="73" x2="212" y2="73" stroke="var(--state-a)" stroke-width="1.6"
      marker-end="url(#ah)"/>
```

**풀이가 딸린 노드** — 그룹으로 감싸면 타이포를 통째로 물려받는다.

```html
<g font-family="ui-monospace, Menlo, monospace" font-size="12.5">
  <rect x="24" y="48" width="140" height="50" rx="8" fill="var(--surface)"
        stroke="var(--line)"/>
  <text x="94" y="70" text-anchor="middle" fill="var(--ink)">Router</text>
  <text x="94" y="86" text-anchor="middle" font-size="10.5" fill="var(--muted)">path → endpoint</text>
</g>
```

**한 구획을 강조하기** — SVG에는 z-index가 없다. 배경을 먼저 칠하고, 그 위에
노드를 얹고, 마지막에 그 구획이 무엇인지 이름 붙이는 작은 라벨을 놓는다.

**불확실성이나 동시성** — `stroke-dasharray="5 4"`에 옅은 채움과 주의 색조.

**접근성** — 모든 `<svg>`에 `role="img"`와, 그림이 무엇을 보여주는지 한 문장으로
말하는 `aria-label`.

두 칸짜리 단순 비교나 범례라면 SVG보다 그냥 HTML·CSS가 낫다. 알아서 흐르고,
테마가 공짜로 따라오고, 쓰는 값도 싸다.

## 규율

- **그림 하나에 생각 하나.** 캡션이 두 줄 필요하면 그림 두 개다.
- **캡션은 그려진 것이 아니라 가져갈 것을 말한다.** 한 줄로.
- **라벨은 대상의 실제 어휘로.** 코드에 나오는 식별자와 경로 그대로.
- **번호는 순서를 뜻한다.** 걸음의 순서에는 번호를 매기고, 나란한 주제에는
  절대 매기지 않는다.
- **한 그림이 페이지를 진다.** 가장 어려운 주장을 지는 그림에 공과 시각적
  무게를 몰아주고, 나머지는 조용하고 균일하게 둬서 그 하나가 신호로 읽히게
  한다. 모든 그림에 나눠 쓴 과감함은 어디에도 쓰이지 않은 것과 같다.
- **산문은 설명하고 그림은 보여준다.** 문단이 이미 말한 것을 되풀이하는 그림은
  장식이다. 지워라.
