# software-digest 스킬 — 설계 기록

상태: 설계 합의 완료, v1 저작 전. (설계 세션 마감 2026-08-05)

## 무엇을 만드나

완성된 개발 작업물 — PR (묶음), 레포지토리, 이슈 딸린 전달물 — 을 처음 받아든
사람이 자기 목적에 맞게 빠르고 정확하게, 총체적으로 이해하도록 돕는
**이해 세션 오케스트레이터** 스킬. HTML 다이제스트를 산출하지만 정체성은
세션이다: 엘리시테이션 → 조사 → 지도 산출 → 검증 루프.

## 문제 프레임 (합의된 원리)

- **이해의 조작적 정의**: 독자가 자기 목적 범위에서 예측("X면 무슨 일이?") ·
  설명("왜 Y인가?") · 위치파악("Z는 어디를 보나?") 질문에 답할 수 있는 상태.
  이것이 스킬의 종료 조건이자 평가 루브릭.
- **이해 = 베이스라인 대비 델타 통합**. 다이제스트의 일: 독자의 베이스라인
  파악 → 의미 있는 델타 선별 → 흡수 가능한 순서로 배열. "표준 X인데 이 세
  곳이 특이하다" 서술이 최고의 압축 기법(스키마 청킹).
- **대상의 의미 층위와 순서**: WHY(왜 존재) → WHAT(블랙박스 행동) →
  HOW-SHAPED(구조·데이터·런타임) → HOW-EXACTLY(코드), WHY-THIS-WAY(결정
  근거)는 각 층의 주석. 피라미드(advance organizer), 선수지식은 JIT 보충.
- **핵심 행위는 요약이 아니라 선별(salience)**: 하중 받는 20% / 보일러플레이트
  / 의도적 특이점을 명시적으로 구분. 다이제스트는 지도지 1:1 백과사전이 아님.
  총체성 = 커버리지가 아니라 정합성(coherence).
- **정확성은 존재론적**: 틀린 지도는 지도 없음보다 나쁨(독자는 검증 불능 상태
  — 오류 비용 비대칭). 접지(file:line), 검증됨/명시됨/추론됨 라벨, 전달 전
  하중 주장 셀프 검증 패스(접지 연극 방지).
- **수동 소비는 이해 착각을 낳음** → 자기 점검 문항 내장 + 라이브 검증 루프.
  Naur: 다이제스트는 이론 전달물이 아니라 독자의 이론 재구축을 가속하는 비계.
- **근거(rationale)는 인공물의 일부**: PR 설명·이슈·커밋에 흩어진 WHY를 채굴,
  의도(이슈)/주장(PR 설명)/실제(diff) 삼각측량. 불일치는 고가치 발견 —
  기술(descriptive) 서술만, 판정 없음.
- **다이어그램은 질문에 답하는 투영**: 그림마다 담당 질문 하나, 장식 금지.
  의도 단위 조직(파일 단위 아님), 대표 시나리오 엔드투엔드 트레이스가 정적
  구조와 동적 행동을 잇는 다리.
- **코드 가이드 유형** (목적 변수가 선별): 읽기 경로 / 시나리오 트레이스 /
  핵심 메커니즘 해부 / 결정 지점 지도 / 로컬 이디엄 사전 / 위험 지대·불변식.

## 결정 원장

1. **이름: 두 언어판 쌍** — 영어판 `software-digest`(원 저작, PR #7), 한국어판
   `software-digest-ko`(같은 설계에서 한국어로 재구현 — 번역 아님, plan-ko.md).
   둘 다 설치·유지한다. [2026-08-05 개정: 단일 스킬 → 언어판 쌍]
2. **정체성: 이해 세션 오케스트레이터** — 산출물은 기질(substrate), 종료
   조건은 위 조작적 정의.
3. **한 스킬, 상황 분류(프레임) 없음** — 목적·베이스라인·예산은 엘리시테이션이
   채우는 자유 변수, 행동은 원리×변수의 함수. 입력 형태 적응(PR이면 델타
   기하, 레포면 시스템 기하)은 분류가 아니라 입력 반응. 목적→강조 예시는
   캘리브레이션용 한 줄들로만(모드 아님).
4. **엘리시테이션 = 적응형 최소 게이트** — 존재는 MUST(생성 전), 분량은 적응
   (호출문에 목적·베이스라인·예산 있으면 한 줄 확인). 무신호 기본값: 일반
   오리엔테이션.
5. **정본 산출 = 단일 자기완결 HTML** — 인라인 CSS/JS, 외부 CDN 금지, 오프라인
   렌더. 다이어그램은 인라인 SVG/CSS 우선(상태→색 인코딩). 계층 줌(접기·목차)
   으로 피라미드 구현. 채팅 인라인 요약 페어링.
6. **산출 위치 = 세션 루트** `<대상-slug>-digest.html` 한 파일, 경로 채팅 명시,
   형상 관리 비대상.
7. **산출 언어 커밋 쌍** — 각 판이 자기 산출 언어에 커밋: 영어판은 English,
   한국어판은 한국어. 라우팅은 두 신호로 성립 — description 자체의 언어(요청
   언어와의 일치) + 역할 서술 속 산출 언어 한 구절("in English"/"한국어로").
   상호 참조 문장은 두지 않는다(신호 중복). 한국어 품질은 환경의 ko-quality가
   자기 발동으로 합성(직교 분할 유지). [2026-08-05 개정: 언어 중립 → 커밋 쌍.
   같은 능력을 언어로 가른 의도적 granularity 예외 — 지시문 언어가 산출 언어
   품질을 지배하고, 주 사용자의 유지보수 언어가 한국어라서]
8. **예산은 범위를 깎지 정확도를 깎지 않음** — "좁지만 참" > "넓지만 흔들림".
9. **검증 기본값** — 문서 자기 점검 3–5문항 상시 내장, 라이브 세션 예측 프롬프트
   1–2회 기본, 풀 퀴즈 옵트인.
10. **판정·가치평가 유보** — 과업을 긍정형으로만 정의, 타 과업(리뷰 등) 대비
    서술을 스킬 텍스트에 넣지 않음.
11. **발동: 직접 호출 위주** — description은 원시 완성 작업물 입력 신호(PR·
    레포·인수인계+대상 지목) 중심, 일반 설명 동사 비클레임, 캐주얼 소형 질문
    제외. `argument-hint` 제공. illustrated-explainer description은 수정하지
    않음(충돌 실관찰 시 재고).
12. **포터빌리티: Claude Code + Codex** — 벤더 중립 표현("사용자에게 질문",
    "서브 태스크 격리 가능 시"), 타 스킬 의존 금지. 시각·교육 기법은
    illustrated-explainer 등에서 저작 시점 증류(borrow, don't load).
13. **배포** — `dot_agents/skills/software-digest/` 정본 +
    `dot_claude/skills/symlink_software-digest` (기존 선례).
14. **구조** — 본문 <500줄 스파인 + `references/` JIT (3-tier). references는
    직교 능력 자료(페이지·다이어그램 기법 증류, 코드 가이드 유형 상세, 자기
    점검 문항 패턴)이지 상황별 플레이북이 아님.
15. **평가** — 이 디렉토리 하위 `evals/`. 픽스처 핀 고정(재현성: 정답 키 부패
    ·런 비교 교란 방지) × 페르소나 자유 변수 매트릭스. 같은 픽스처에 페르소나
    2종을 붙여 목적-반응성(메커니즘)을 직접 시험. 페르소나는 독자 시뮬레이터
    초기화이자 게이트 대본(게이트 로직도 시험됨). 레이어 1 = 계약 준수 이진
    감사(상시), 레이어 2 = 코드 접근 차단된 독자 시뮬레이터의 프로브 배터리
    (예측/설명/위치파악 × 층위, 정답 키는 별도 런이 저작) vs 무다이제스트
    대조군(대개정 시만). 수동 트리거 전용. 한계 명시: LLM 독자는 인간 프록시
    — 산출물의 정보 충분성·조직 품질을 재는 것.
16. **접근 불가 소스·거대 입력** — 명시하고 가용 범위로 진행, 미지는 미지로
    표기.

## 기각한 경로 (재방문 방지)

- **목적별 프레임 3종 플레이북** (리뷰/온보딩/OSS) — 자유 변수로 충분, 명명된
  카테고리는 하이브리드 상황을 오분류. 참고: 비교 개념도 스킬에서 완전 제거
  (후보 N개면 N회 실행; "아는 대안 대비" 서술은 베이스라인 활용의 일반 원리로
  자연 발생).
- **마크다운+mermaid 정본** — 일회성+공유 산출물엔 HTML의 가독성·표현력·계층
  줌 구현력이 우위.
- **evals-first 콘텐츠 게이트** ("실측 실패만 담기") — 충분히 사유된 추상으로
  v1 직행. 평가는 사후 검증·회귀 장치로 재배치.
- **재진입 상태 기계** — 산출물 재방문으로 충분.
- **한국어 원칙 내장** — ko-quality와 직교 분할.
- **리뷰와의 경계 서술을 스킬에 포함** — 설계 세션의 사고 도구였을 뿐, 스킬은
  긍정형 정의만(맥락 유출 금지).
