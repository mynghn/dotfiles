한국어판(`software-digest-ko`)의 /goal 루프 실측 기록. 실행 정본은

**매트릭스** = `SD_SKILL=software-digest-ko ./evals/run.sh` 전 체크 + 시나리오별
L4 저지(동결 rubric 9항목 × 3). 러너와 저지는 매번 프레시 서브에이전트이고 메이커와
컨텍스트가 분리된다.

## 저작 (매트릭스 이전)

한국어로 먼저 전부 저작한 뒤 영어판을 **커버리지 대조표로만** 썼다. 대조에서
한국어 초안이 재도출하지 못한 규칙 아홉 개가 나왔다: 의도 기반 조직, 충실성 계약,
대상의 모양(변경 대 시스템), 상태 기본값과 미착륙 작업, 도착한 조각 사이의 관계,
보여주고 단언하지 않기, 순서 제약, 템플릿 시험, 자기완결 문서 계약. 이 중 앞의
둘은 루브릭 항목 1·6에 직접 걸리므로 빠진 채 매트릭스에 들어갔으면 그대로
FAIL이었다.

**대조가 값을 한 지점이 여기다.** 설계 원칙에서 재도출하는 방식은 문장 구조를
들여오지 않는 대신 규칙을 빠뜨린다. 번역하지 않되 마지막에 대조하는 순서가 둘을
다 얻는다.

ko-quality 중량 검수 3기(humanizer / style-guide / grammar-checker+principles)를
격리 병렬 실행 — **S1 0건**, 36곳 교정. 실제 결함은 하드 랩이 낱말을 쪼갠 세 곳
(`들어 간다`·`메커니즘 이다`·`요구 하면서` — 렌더링 시 공백이 생긴다), 간접인용
어미(`바꿔라는`), 영어식 도입 콜론 4곳, 그리고 패키지 안에서 흘러버린 용어
(레포지토리/레포, 사용자/독자, 도식/다이어그램, "문서"가 다이제스트와 소스 문서를
겸용). 가운뎃점 일괄 교체와 줄표 밀도는 반려 — 검사기 자신이 권고 등급으로 매겼고
형제 문서(design.md·plan-ko.md)가 이미 쓰는 관례다.

### 실패 1 — s1 basis-honest: `verified`에 검증 행이 없었다

`data-basis="verified"` 각주가 "`func (…) onMouse` 전수 검색의 세 번째 히트가
spyRenderer"라고 했는데 실제 히트는 둘이고 spyRenderer는 메서드를 하나도 선언하지
않는다. 같은 각주의 "자체 상태가 없다"도 `calledReset bool`과 어긋났다.

원인은 §5 표의 **비대칭**이다. `stated`에는 "명시한 출처를 다시 읽어라" 행이 있는데
`verified` — 확인했다고 주장하는 라벨 — 에는 아무 행도 없었다. 그래서 *확인 절차를
서술하는 문장*이 목록에 오르지 않고 통과했다. 목록에 없는 주장이 살아남는다는
규칙이 자기 자신에게도 적용된 셈이다.

수정(`238ee10`): `verified` 라벨 행 추가. 산문 형태("두 사례 모두 테이블 루프
안")까지 덮고, 산출 계약의 라벨 정의에 "확신은 확인이 아니다"를 못 박았다.

### 실패 2 — s2 fidelity: 그림이 자기 상세와 어긋났다 (미해결)

그림2가 stdin에 없는 블록 셋을 출력에 "살아 있던 그대로" 그렸는데, 바로 아래 접힌
상자의 실제 실행 결과에는 그 셋이 없다. 저지가 같은 입력으로 재현해 확인했다.

표의 접힌 상자 행은 **요약 → 상세**만 덮는다. 여기서 어긋난 것은 **그림 → 상세**다.
그림이 요약 자리에 설 수 있다는 것을 표가 모른다.

매트릭스 2에서 이 실패가 다시 나오는지부터 본다 — 계통적이면 표에 행을 더하고,
일회성이면 더하지 않는다. 진행 규칙상 턴당 클러스터 하나만 고치므로 매트릭스 2는
이 결함을 안고 들어간다.

**디스패치 오염을 한 번 만들었다가 되돌렸다.** 매트릭스 2의 s2 러너 프롬프트에
그림↔실측 대조 지시를 넣었는데, 그건 스킬이 져야 할 일을 프롬프트로 메우는 것이라
러너를 죽이고 깨끗한 프롬프트로 다시 띄웠다. 러너 디스패치에 담아도 되는 것은
plan-ko가 지정한 두 가지(픽스처 불변, 나눠 쓰기)뿐이다. 나머지를 넣으면 매트릭스가
스킬이 아니라 프롬프트를 재게 된다.

**두 실패가 다 닫혔고, 닫힌 방식이 다르다.**

`verified` 행은 겨눈 곳에 정확히 맞았다. s1 러너가 "이 저장소의 `renderer` 구현은
둘뿐"이 `spyRenderer`를 빠뜨린 것을 전달 전에 잡아 "제품 코드 기준"으로 좁혔고,
확인을 서술하는 문장의 정규식이 실제 실행한 명령과 글자 단위로 어긋난 것도 잡았다.
s3 러너는 `verified` 라벨이 딛고 선 검색 셋을 다시 돌렸다. 저지들도 같은 주장을
독립 재수행해 확인했다.

s2의 fidelity는 **표를 고치지 않고** 닫혔다. 이번 러너는 병합 동작을 스크래치패드
사본에서 실제로 돌리고 그 실행 결과를 `verified` 근거로 삼았다 — `verified` 행이
"검색 결과를 말하는 주장이면 그 검색을 다시 돌려라"라고 요구하자, 실행 결과를
그리는 그림에도 같은 요구가 옮겨붙은 것이다. 저지가 파이프라인을 직접 재실행해
그림3의 출력 순서를 한 항목씩 대조했고 전부 맞았다.

그래서 **그림 → 상세 행은 추가하지 않았다.** 매트릭스 1의 한 번은 계통이 아니라
표본 하나였고, 근거 없이 행을 늘리면 표가 길어진 만큼만 무뎌진다.
