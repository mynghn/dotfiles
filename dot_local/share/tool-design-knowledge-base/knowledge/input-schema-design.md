**What it is.** The design of a tool's input parameters — the JSON Schema the agent fills to call it: names, types, required-vs-optional, enums over free-text, defaults, value constraints, and the overall shape. The goal is poka-yoke: structure the schema so invalid or ambiguous calls are hard or impossible to represent, rather than relying on the model to be careful. This is the *contract side* of the call — distinct from how the result comes back.

**Why / Evidence.** Schema shape directly drives call accuracy. Anthropic (2025) recommends preferring `user_id` over a bare `user`; the rationale is that an unqualified `user` invites the model to pass a name, email, or object interchangeably. OpenAI (2025) is explicit: "Use enums and object structure to make invalid states unrepresentable" — a toggle should not accept both `on` and `off` at once; the schema should forbid the logical impossibility. Format choice matters as much as naming: Anthropic's "Building effective agents" (2024) found models repeatedly erred on relative filepaths after `cd`, and switching the parameter to *always require absolute paths* made the model "use this method flawlessly" — a one-field change that eliminated a class of errors. Their three format heuristics: give the model enough tokens to "think" before it commits, keep the format close to what occurs naturally in internet text, and avoid overhead like line-counting or string-escaping. OpenAI adds two leverage points: `strict: true` with `additionalProperties: false` and all-required fields guarantees schema-conformant calls (optional fields modeled as a `null` type union), and don't make the model fill arguments you already know — inject known context (IDs, tenant, auth) in code instead of widening the schema. MCP (2025) standardizes the carrier: `inputSchema` is JSON Schema (`type`, `properties`, per-property `description`, `required`), so enums, types, and constraints are first-class and machine-validated.

**How to apply.** (1) Name for the value, not the concept — `user_id`, `start_date`, not `user`, `when`; an unambiguous name halves the model's guessing. (2) Replace free-text strings with `enum` wherever the valid set is closed (status, mode, sort order) — this both constrains the model and documents the options inline. (3) Make illegal states unrepresentable: use object structure / `oneOf` so contradictory or mutually-exclusive args can't coexist; mark `required` honestly and reject extras with `additionalProperties: false`. (4) Pick error-resistant formats: absolute over relative paths, ISO dates over "next Tuesday", a single canonical shape over several accepted ones; avoid formats demanding exact counts or escaping. (5) Give every parameter a `description` stating purpose and format (OpenAI: an intern should be able to use it from the schema alone). (6) Drop parameters whose value your code already knows. (7) Iterate empirically — run many example inputs and watch where the model mis-fills, then tighten the schema, since the parameters you think are obvious often aren't.

**Takeaway.** Treat the input schema as a guardrail, not a form: every enum, type, required-flag, and canonical format you add is a class of wrong calls the agent can no longer make. The best schema makes the correct call the only expressible one.
